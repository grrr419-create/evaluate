# evaluate · 업무환경 심리평가

GitHub Pages 화면과 Supabase Edge Function·Postgres로 운영합니다. PC와 모바일에서 같은 주소를 사용하며 운영자의 PC를 켜 둘 필요가 없습니다.

## 사용 흐름

- 평가자는 입력란 없이 **평가 참여하기** 버튼을 누릅니다. 안내를 확인하고 모든 문항에 응답한 뒤 제출 확인창에서 제출합니다.
- 관리자는 현재 평가의 제출 인원과 문항별 통계를 확인합니다. 대상 명단, 미참여자, 부서별 완료 조건은 없습니다. 제출이 1건 이상이면 통계와 다운로드가 제공됩니다.
- 다음 부서를 평가하기 전 기존 엑셀을 내려받고 결과 초기화를 실행합니다. 확인창에서 결과 초기화를 확정합니다.
- 초기화하면 현재 답변, 참여 기록, 중복 확인 정보가 삭제되고 평가자 세션이 만료됩니다. 같은 브라우저로 새 평가에 참여할 수 있습니다.
- 문항은 고정입니다. 명단 및 문항 업로드 기능은 제공하지 않습니다.

## 중복 참여와 정보 범위

브라우저는 무작위 토큰을 localStorage에 보관합니다. 서버는 평가 회차별 비밀값으로 변환한 토큰만으로 중복 참여를 확인합니다. 제출 전에 다시 접속하면 같은 참여 기록을 사용하고 이전 세션을 만료시킵니다. 제출 후 다시 참여하면 “평가는 1회 참여할 수 있습니다.”라고 안내합니다. 관리자 초기화는 참여 기록을 삭제하고 회차 비밀값을 바꾸므로 같은 브라우저에서 다시 참여할 수 있습니다. 작성 중인 답변은 브라우저를 닫으면 저장되지 않습니다.

같은 회사 와이파이를 이용하는 동료가 차단되지 않도록 IP당 1명 제한은 적용하지 않습니다. IP는 해시 처리 후 단시간의 과도한 접속 시도 제한에만 사용하며 답변에 포함하지 않습니다. 응답 테이블에는 무작위 응답 번호와 답변만 저장하며 닉네임·사번·성명·IP·기기 토큰·제출 시각을 저장하지 않습니다. 실제 신원을 확인하지 않으므로 다른 기기·브라우저·시크릿 모드 또는 사이트 데이터 삭제까지 동일인으로 판별할 수는 없습니다.

관리자와 평가자 권한은 3시간 유효한 임의 세션으로 분리합니다. `evaluate_private` 스키마의 테이블과 함수는 공개·일반 인증 역할에 직접 노출되지 않습니다. 외부 RPC는 `service_role`만 실행할 수 있으며, Edge Function의 요청 검사 후 DB에서 세션과 역할을 확인합니다. 브라우저에는 서비스 키가 없습니다. CORS는 인증을 대체하지 않습니다.

접속·제출·집계·초기화는 동일 설정 행을 잠그는 트랜잭션에서 처리합니다. 중복 제출과 초기화 이전 세션의 새 회차 제출을 거부합니다. 관리자 화면에는 참여자 목록이 없으며 개별 답변은 관리자 다운로드 API에서만 제공합니다.

## 엑셀

`평가 현황`, `문항별 통계`, `개별 응답 안내` 및 참여자별 `응답 001`, `응답 002` 시트로 구성됩니다. 각 응답 시트에는 한 참여자의 모든 문항 답변이 있습니다. 시트 번호는 임의 UUID 정렬로 정하며 제출 순서를 뜻하지 않습니다. 텍스트는 수식으로 실행되지 않는 문자열 셀로 저장합니다.

개별 답변 보관 기능 도입 이전 제출은 합계만 남아 있으므로 복원하지 않습니다. 기존 합계는 보존하고 엑셀에 개별 답변 미보관 건수를 안내합니다. 초기화 이후의 새 제출은 모두 개별 답변을 보관합니다.

## 구성과 배포

| 경로 | 역할 |
| --- | --- |
| `public/` | 화면 원본 |
| `docs/` | GitHub Pages 게시 파일 |
| `supabase/functions/evaluate/index.ts` | API 요청 검사와 DB 호출 |
| `supabase/migrations/` | 데이터 구조, 권한, 접속·제출·통계 API |
| `tools/build.mjs` | 허용된 정적 파일만 복사 |
| `tools/prepare-seed.mjs` | 문항·안내·관리자 설정으로 최초 설치 SQL 생성 |
| `tests/` | 실제 운영 데이터와 분리된 가상 데이터 테스트 |
| `.private/` | 관리자 설정·설치 자료. 게시 금지 |

신규 설치는 SQL migration을 파일명 순서대로 모두 실행한 뒤, 문항·안내만 들어 있는 `.private/frozen-data.json`과 `.private/관리자설정.json`으로 `node tools/prepare-seed.mjs`를 실행합니다. 생성된 비공개 install.sql을 Supabase SQL Editor에서 한 번 실행합니다. 초기 설치 자료에는 명단이 필요 없으며 source는 허용된 필드만 저장합니다.

기존 운영 환경에는 아직 적용하지 않은 migration을 순서대로 한 번씩 적용합니다. 2.0.1에서 2.1.0으로 전환할 때는 `202609030005_device_participation.sql`만 추가 적용합니다. 이 migration은 닉네임 열과 중복 조건을 제거하며 기존 답변·통계·기기 참여 기록을 보존합니다. 초기화는 실행하지 않습니다. 과거 migration을 최신 운영 DB에 다시 적용하면 함수가 이전 버전으로 덮어써지므로 재적용하지 마세요.

Edge Function `evaluate`는 `verify_jwt=false`로 배포하고 내부의 별도 세션 검증을 사용합니다. 환경 변수 `ALLOWED_ORIGINS`에는 Pages 출처를 설정합니다. `SUPABASE_URL`과 `SUPABASE_SERVICE_ROLE_KEY`는 서버에서만 사용합니다. `public/config.json`의 apiUrl을 설정한 후 `node tools/build.mjs`로 docs를 만듭니다. Pages 게시 소스는 main 브랜치의 /docs입니다. 비밀번호·설치 SQL·데이터 백업은 공개 저장소에 올리지 않습니다.

2.0 버전의 초기화 오류 수정에는 `202609030004_reset_conditions.sql`을 적용합니다. 운영 PostgREST의 safeupdate 설정을 유지하고 모든 삭제·수정 구문에 대상을 명시합니다. 평가 이름은 고정하며 초기화 창에 이름 입력란이 없습니다.

## 검증

Node.js 22 이상에서 `npm install`, `npm test`, `npm run build`를 실행합니다. PGlite의 Postgres·pgcrypto로 버튼 참여, 공유 IP 참여, 브라우저 토큰 지속성, 동시 제출, 초기화, 권한, 기존 자료 전환 및 XLSX를 검증합니다.

`node tools/preview.mjs`는 운영 DB와 연결하지 않는 가상 평가를 실행합니다. 미리보기 관리자 계정은 tests/fixtures.mjs에 있으며 실제 운영 계정과 다릅니다.
